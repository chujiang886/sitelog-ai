# BOIP 2.2.4 MinIO 图片存储切换 — 设计文档

> 阶段：Phase 2.2 Sprint 3（2.2.4 MinIO 图片存储切换）
> 身份：BOIP AI 高级研发负责人 / 存储架构
> 关联：Phase 1 / T08 本地上传、TD-015（MinIO 去重 + 租户隔离）、2.2.1 Provider 抽象（同构三模式）
> 守约：不降低 local_ci 标准、不修改扫描规则、不关闭 pending、不编造工程参数、
> 不设置未经审核 verified=true、engineering_enabled 保持 false、外部服务支持
> mock / disabled / fallback。

## 〇、目标与约束

将图片存储从「硬编码本地路径」升级为**可扩展对象存储抽象**（`StorageBackend`），
支持 LocalStorage（开发/CI 默认）与 MinIOStorage（生产可配置），不破坏已有上传 API。

**红线**：
- 开发环境继续支持 LocalStorage（默认，CI 用）；
- MinIO 经配置切换（`BOIP_STORAGE_BACKEND=minio`），密钥**仅来自 .env**，禁止提交；
- 不破坏已有上传 API（`POST /api/uploads`、`GET /api/uploads/{id}`）；
- 支持租户隔离、对象路径规划、内容 hash 去重；
- **CI 不能依赖真实 MinIO**（用 local / memory 后端跑测试）。

## 一、当前存储架构

`backend/app/core/storage.py` 现状（Phase 1 / T08 占位）：

| 项 | 现状 |
|---|---|
| 根目录 | `BOIP_STORAGE_ROOT` 环境变量，缺省 `backend/storage/uploads` |
| 路径规划 | `build_image_path(tenant_id, sha256, ext)` → `{root}/{tenant_id}/{sha256}.{ext}` |
| 去重 | 上层 uploads 路由按 `sha256 + tenant_id` 命中复用 DB 行 |
| 写入 | `uploads.py` 直接 `storage_path.write_bytes(content)` |
| 读取 | `vision_tasks.py` 直接 `Path(image.storage_path).read_bytes()` |
| 抽象 | 无；Local 硬编码 |

**不足**：不可切换后端；MinIO 无法接入；无统一 `save/read/delete` 接口；
测试依赖真实文件系统（`test_uploads.py` monkeypatch `resolve_storage_root`）。

## 二、抽象设计：StorageBackend

新建 `backend/app/core/storage_backends.py`：

```
StorageBackend(ABC)
├─ save(*, key, content, tenant_id=None) -> str     # 返回逻辑 key
├─ read(*, key) -> bytes                            # 按 key 取字节
├─ delete(*, key) -> None                           # 删除
├─ resolve_key(tenant_id, sha256, ext) -> str       # 路径规划
└─ backend_name: str                                # local / minio / memory
```

三种实现：

| 实现 | 用途 | 外部依赖 | 密钥来源 |
|---|---|---|---|
| `LocalStorage` | 开发/CI 默认 | 文件系统 | 无 |
| `MinIOStorage` | 生产可配置 | minio SDK（懒加载） | 仅 .env（MINIO_*） |
| `MemoryStorage` | 测试 mock（对应外部服务 mock 模式） | 无 | 无 |

**工厂 `get_storage_backend()`**：
- 读 `BOIP_STORAGE_BACKEND` 环境变量（默认 `local`）；
- `local` → `LocalStorage()`；`memory` → `MemoryStorage()`（测试用 mock）；
- `minio` → `MinIOStorage()`：构造时校验 `MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET`
  是否齐全，**缺失即抛 `StorageConfigError`**（fail-fast，与 2.2.1 factory 同构）；
- 未知值 → 抛 `StorageConfigError`。

> 三模式映射（满足「外部服务支持 mock/disabled/fallback」）：
> - mock = `MemoryStorage`（CI/单测，无真实 MinIO）；
> - 默认 = `LocalStorage`（dev/fallback）；
> - `minio` 未配置 → fail-fast 报错（不让错误静默降级成空存储）。

## 三、LocalStorage 路径规划与去重

- `resolve_key(tenant_id, sha256, ext)` = `f"{tenant_id}/{sha256}.{ext}"`
  → **租户隔离**（tenant_id 作前缀）+ **内容 hash 去重**（sha256 作对象名，同内容必同 key）。
- `save`：写 `{root}/{key}`；`root = storage.resolve_storage_root()`（沿用既有
  `BOIP_STORAGE_ROOT` 机制，保证 `test_uploads.py` monkeypatch 仍生效）。
- `read`：兼容旧数据 —— 若 `key` 为绝对路径且存在则直接读，否则读 `{root}/{key}`。
- `delete`：删除 `{root}/{key}`（存在才删）。

---

## 四、MinIOStorage

- 懒加载 `from minio import Minio`（SDK 未装且 `backend=minio` 时抛清晰错误）。
- 配置仅来自环境变量（**禁止硬编码**，满足红线）：
  - `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`、
    `MINIO_SECURE`（默认 true）。
- `save`：`client.put_object(bucket, key, BytesIO(content), length=len(content))`。
- `read`：`client.get_object(bucket, key).read()`。
- `delete`：`client.remove_object(bucket, key)`。
- bucket 不存在 → 构造时尝试 `make_bucket`（已存在忽略），或抛清晰错误。
- `resolve_key` 同 LocalStorage（保证跨后端 key 一致，便于迁移）。

---

## 五、上传 API 改造（不破坏契约）

`backend/app/api/uploads.py`：
- 移除直接 `build_image_path` + `write_bytes`；
- 改为：
  ```
  backend = get_storage_backend()
  key = backend.resolve_key(tenant_id=str(tenant_id), sha256=..., extension=...)
  storage_path = backend.save(key=key, content=processed.content, tenant_id=...)
  ```
- `storage_path` 存为逻辑 key（如 `tenant_id/sha256.ext`），DB schema 不变；
- `GET /api/uploads/{id}` 返回 `storage_path`（key）不变。

`backend/app/tasks/vision_tasks.py`：
- 读取图片改为 `content = get_storage_backend().read(image.storage_path)`，
  保留旧绝对路径兼容（`LocalStorage.read` 回退），失败标 `STORAGE_READ_FAILED`。

---

## 六、迁移（migrate）

- 因 key 规划统一为 `{tenant_id}/{sha256}.{ext}`，Local→MinIO / MinIO→Local 迁移
  即「按 key 逐对象 copy」：
  - `migrate_storage(src, dst)`：遍历 src 列举 key → `dst.save(key, src.read(key))`；
  - 保留 DB `storage_path` 不变（key 跨后端一致）。
- 单测覆盖：memory→local、local→memory 双向迁移字节一致。

---

## 七、测试方案

新增 `backend/tests/test_storage_backends.py`（覆盖上传/读取/删除/迁移）：

1. **save/read**：local / memory 写入后 read 回字节一致；
2. **delete**：删除后 read 抛 `FileNotFoundError`；
3. **tenant 隔离**：不同 tenant 的 key 前缀不同，互不可见；
4. **hash 去重**：相同 content → 相同 key → save 幂等（不重复写）；
5. **minio 配置缺失**：`BOIP_STORAGE_BACKEND=minio` 且无 `MINIO_*` → 抛 `StorageConfigError`（CI 不依赖真 MinIO）；
6. **migrate**：memory→local / local→memory 字节一致；
7. **uploads 集成**：`test_uploads.py` 仍绿（local 后端 + monkeypatch 生效）。

**CI 不依赖真实 MinIO**：全部测试用 local / memory；minio 仅测「未配置即报错」分支。

## 九、风险

- R1（中）：minio SDK 未安装 → 仅 `backend=minio` 时懒加载报错；CI 用 local/memory，不受影响。
- R2（低）：`storage_path` 由绝对路径变逻辑 key → vision_tasks 读路径兼容旧数据（LocalStorage.read 回退）。
- R3（低）：扫描规则 —— 新代码无 `threshold=` 数值、无业务词+数值、无硬编码品牌/型号。
