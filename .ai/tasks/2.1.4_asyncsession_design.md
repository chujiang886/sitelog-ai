## 1. 当前数据库访问方式

### 1.1 引擎与 Session 工厂（`backend/app/db/session.py`）

- 同步引擎：`create_engine(url, future=True, pool_pre_ping=True)`，缺省 `sqlite+pysqlite:///:memory:`（见 `_resolve_database_url`）。
- 工厂：`SessionLocal: sessionmaker[Session]`（同步），`class_=Session`。
- 依赖：`get_db() -> Generator[Session, None, None]`，`yield SessionLocal()`，finally `db.close()`。
- 注释明确写明 Phase 0 决策：`走同步 ORM（alembic 默认同步），FastAPI 路由可使用 Depends(get_db)`。

### 1.2 包导出（`backend/app/db/__init__.py`）

```python
from app.db.base import Base, naming_convention
from app.db.session import SessionLocal, engine, get_db
__all__ = ["Base", "SessionLocal", "engine", "get_db", "naming_convention"]
```

### 1.3 ORM 模型（`backend/app/db/models/`，9 张表）

`tenant / user / project / agent / knowledge_rule / knowledge_case / audit_log / conversation / message / image / threshold_config`（实际 10+ 表）。
所有模型继承 `app.db.base.Base`（DeclarativeBase，**同步/异步通用，无需改动**）。

### 1.4 实际落库位置

## 2. 同步/异步混用位置（阻塞风险点）

**根因**：`get_db` 产出**同步 `Session`**，却被注入到 `async def` 路由中；路由内 `db.commit()` / `db.query().all()` 等是阻塞调用，会卡住 asyncio 事件循环。

| # | 文件 | 行 | 混用点（同步操作在 async 路由内） |
|---|------|----|------------------------------------|
| 1 | `api/conversations.py` | 155-201 | `create_conversation`：`db.query(Project)`、`db.add(conv)`、`db.commit()`、`db.refresh(conv)` |
| 2 | `api/conversations.py` | 204-232 | `get_conversation`：`_require_conversation` 内 `db.query(...).one_or_none()`；`db.query(Message).filter_by(...).order_by(...).all()` |
| 3 | `api/conversations.py` | 235-357 | `append_message`：`_require_conversation`；`db.add(user_msg)`、`db.flush()`；`db.query(Message).order_by(...).limit(20).all()`；`db.add(assistant_msg)`、`db.commit()`、`db.refresh(assistant_msg)` |
| 4 | `api/conversations.py` | 360-398 | `list_messages`：`_require_conversation`；`db.query(Message)...count()`；`db.query(...).offset().limit().all()` |
| 5 | `api/vision.py` | 64-95 | `analyze_image`：`db.query(Image)`、`db.query(Image).filter_by(id=image.id).one()` |
| 6 | `api/uploads.py` | 127-212 | `upload_image`：`db.query(Project)`、`db.query(Image)`、`db.add(image)`、`db.commit()`、`db.refresh(image)`（×2） |
| 7 | `api/uploads.py` | 229-246 | `get_image`：`db.query(Image)` |
| 8 | `api/uploads.py` | 109 / 145 | **同步调用** `process_image(image_id=...)`（后台任务，含同步 `db.commit`），直接阻塞 event loop |
| 9 | `tasks/vision_tasks.py` | 35-43 / 76-173 | `process_image` 用 `SessionLocal()` 同步会话：`session.get / commit / refresh / close`（后台任务，非路由） |

> 注：`api/health.py`、`api/analysis.py`、`api/agents.py`、`api/knowledge.py`、`api/projects.py`、`api/report.py` **不注入 `get_db`**，无混用风险，不在改造范围。

## 3. 改造方案

### 3.1 `session.py`（核心 —— 引入异步，保留同步兼容）

```python
from sqlalchemy.ext.asyncio import (
    AsyncSession, async_sessionmaker, create_async_engine,
)
from sqlalchemy.orm import Session, sessionmaker
from sqlalchemy import create_engine

# —— 保留：同步（供 test_db.py / vision_tasks.py / alembic 兼容） ——
engine = _build_engine(_resolve_database_url())                  # 同步引擎
SessionLocal = sessionmaker(bind=engine, autoflush=False,
                            autocommit=False, expire_on_commit=False,
                            class_=Session)

def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# —— 新增：异步（供请求路径路由） ——
def _resolve_async_url() -> str:
    url = os.getenv("DATABASE_URL_ASYNC", "").strip()
    if url:
        return url
    # SQLite 内存回退需 aiosqlite；StaticPool 保证单连接共享内存库
    return "sqlite+aiosqlite:///:memory:"

async_engine = create_async_engine(
    _resolve_async_url(),
    pool_pre_ping=True,
    **({"poolclass": StaticPool,
        "connect_args": {"check_same_thread": False}}
       if _resolve_async_url().startswith("sqlite") else {}),
)
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine, class_=AsyncSession,
    autoflush=False, autocommit=False, expire_on_commit=False,
)

async def async_get_db() -> AsyncIterator[AsyncSession]:
    async with AsyncSessionLocal() as session:
        yield session
```

要点：
- **同步 `engine / SessionLocal / get_db` 原样保留** → `test_db.py` 直接断言它们，保持绿；`vision_tasks.py` 继续用同步会话。
- **新增 `async_engine / AsyncSessionLocal / async_get_db`** → 路由改用。
- `:memory:` 异步回退用 `aiosqlite + StaticPool`，与现有同步测试 `StaticPool` 行为对齐（单连接共享内存库，避免每次连接新建空库）。

### 3.2 路由改造（3 个模块，仅改会话机制与 `db.*` 调用风格）

统一替换：
- `from sqlalchemy.orm import Session` → `from sqlalchemy.ext.asyncio import AsyncSession`
- `db: Session = Depends(get_db)` → `db: AsyncSession = Depends(async_get_db)`
- `db.query(Model).filter_by(...).one_or_none()`
  → `(await db.scalars(select(Model).filter_by(...))).one_or_none()`
- `db.query(Model).filter_by(...).order_by(...).all()`
  → `(await db.scalars(select(Model).filter_by(...).order_by(...))).all()`
- `db.query(Model)...count()`
  → `await db.scalar(select(func.count()).select_from(Model).filter_by(...))`
- `db.add(x)` → 不变（无需 await）
- `db.commit()` → `await db.commit()`
- `db.refresh(x)` → `await db.refresh(x)`
- `db.flush()` → `await db.flush()`
- helper `_require_conversation(db: Session, ...)` → `db: AsyncSession` + 内部 `await`
- `select` / `func` 从 `sqlalchemy` / `sqlalchemy.sql` 导入

**API 契约不变**：HTTP 路径、请求体、响应信封 `{success, data}`、tenant 隔离 400/404、`pending_verification` 字段 —— 全部原样保留。仅实现机制由同步改为异步。

### 3.3 后台任务 `vision_tasks.process_image`（最小改动，消除路由级阻塞）

- **不修改 `process_image` 内部逻辑**（保持同步 `SessionLocal` 会话，业务不变）。
- 在调用方（`uploads.py` line 109 / 145，`vision.py`）将同步阻塞调用改为线程卸载：
  ```python
  await asyncio.to_thread(process_image, image_id=image_id)
  ```
- 效果：路由不再因 `process_image` 内的 `db.commit` / 文件读取阻塞事件循环；`process_image` 逻辑零改动（满足"禁止修改业务逻辑"）。
- **备选（不在本阶段，列为后续）**：将 `process_image` 整体改为 `async def` + `AsyncSession`。成本更高（波及 `test_vision_task_runner.py`），本阶段不做。

### 3.4 alembic（`env.py`）—— 不在改造范围

- 保持同步 `engine_from_config`。
- URL 兼容策略：应用侧异步引擎读取 `DATABASE_URL_ASYNC`（缺省推导 `aiosqlite`）；alembic 读取 `DATABASE_URL`（同步驱动，如 `sqlite+pysqlite` / `postgresql+psycopg`）。二者可并存，互不干扰。
- 若 `DATABASE_URL` 未配，alembic 维持既有 `sqlite+pysqlite:///:memory:` 回落。

### 3.5 `db/__init__.py` 导出补充

```python

    SessionLocal, engine, get_db,          # 同步（保留）
    async_engine, AsyncSessionLocal, async_get_db,  # 新增异步
)
__all__ = ["Base", "SessionLocal", "engine", "get_db",
           "async_engine", "AsyncSessionLocal", "async_get_db",
           "naming_convention"]
```

### 4.3 依赖与风险

- **新增运行时依赖**：`aiosqlite`（SQLite 异步驱动）。`asyncpg` 仅在使用真实 PostgreSQL 异步 URL 时需要（CI/本地默认 SQLite，暂不强制）。
  - 需在 `backend/requirements.txt` / `pyproject.toml` 登记 `aiosqlite`。
- **测试内存库一致性风险**：异步 `:memory:` 必须用 `StaticPool` 单连接，否则每次 `AsyncSession` 新建空库导致测试失败 —— 设计已用 `StaticPool` 规避，与现有同步测试一致。
- **跨引擎可见性**：路由（异步引擎）与 `process_image`（同步 `SessionLocal`）在 `:memory:` 下是不同库。测试中若断言 `process_image` 写入的结果，需通过 `monkeypatch` 让 `vision_tasks.SessionLocal` 指向测试同步引擎（现有 `test_uploads.py` 已可此类注入）。本阶段仅保证路由不阻塞，写入可见性沿用现有测试机制。
