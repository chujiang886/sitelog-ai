## 一、当前 Environment Agent 分析

### 1.1 现状（代码实读结论，`agents/environment/agent.py`，378 行）

| 维度 | 现状 |
|------|------|
| 版本 | `1.0.0-phase1`，Phase 1/T09 实现 |
| 输入契约 | `input_data = {address, coordinates{lat,lng}, vision_result, region_hint}` |
| 数据来源 | **仅 LLM 常识推理**（track text，`build_router_from_config(role=TEXT)`），无任何真实外部数据 |
| 工具声明 | `tools = ("weather_mcp", "gis_mcp")` —— **仅声明、从未连接**（Phase 1 注释明示） |
| 输出字段 | climate_zone / prevailing_wind / solar_exposure / noise_level_hint / regulatory_hints / regional_material_preference / summary |
| 三条路径 | ①无上下文 → `environment_placeholder`（facts 空 + gaps）；②LLM 关闭/降级 → placeholder（pending=True）；③LLM 成功 → `environment_analyzed`（pending=False，facts 填充） |
| 防编造 | System Prompt 明确“你无法获取真实气象/地图数据，任何数值不得编造”；gaps 恒含 `weather_data/gis_data: pending_verification` |
| 测试 | `tests/agents/test_environment.py` 8 个用例（身份/工具/占位/降级/失败/JSON 解析/脏输入） |

### 1.2 关键判断

- **现有 `pending_verification=False` 语义有瑕疵**：LLM 成功路径把 pending 置 False，但 LLM 输出仍是**常识推理**而非实测数据。2.2.1 必须重新定义：`pending_verification` 只有在**真实数据源命中**时才可为 False；LLM 推理结果永远保持 pending（本设计 §6 解决）。
- 现有三路径降级骨架**质量高、可复用**——真实数据接入应作为“第四条路径”插在 LLM 之前，而非重写。

## 三、外部数据源候选分析

> ⚠️ 按主理人指令：**本文档不选定真实 API**，只做候选盘点与决策框架。真实选型待 ADR 批准后另行确认密钥/预算。

### 3.1 地理编码 + GIS（G1/G6）

| 候选 | 优势 | 劣势 | 合规/成本 |
|------|------|------|----------|
| A1 高德开放平台 | 国内地址解析精度最好；文档全；免费额度日 5k+ | 商用需授权；Key 管理 | 国内合规✅；个人开发者免费层 |
| A2 腾讯位置服务 | 同为国内主流；WebService API 齐全 | 同上 | 同上 |
| A3 百度地图开放平台 | 覆盖广 | 坐标系 BD-09 需转换（高德/腾讯为 GCJ-02） | 同上 |
| A4 OpenStreetMap Nominatim | 免费、开源 | 国内地址精度差；公共实例限流 1 req/s；生产不可靠 | 仅适合离线兜底 |

### 3.2 气象/风况（G3）

| 候选 | 优势 | 劣势 | 合规/成本 |
|------|------|------|----------|
| B1 Open-Meteo | 免费无 Key（非商用）；含 **Historical/Climate API** 可取多年风向风速统计；返回结构干净 | 商用需付费版；国内访问稳定性待验证 | 免费层宽松 |
| B2 和风天气（QWeather） | 国内节点稳；有历史天气接口 | 免费层额度有限；历史数据在付费层 | 国内合规✅ |
| B3 彩云天气 | 国内实时/预报强 | 历史统计弱（我们要的是**多年统计**而非实时预报） | 按量计费 |
| B4 NOAA/ERA5 再分析数据 | 学术级权威 | 接入复杂（GRIB/NetCDF），远超本阶段需要 | 免费但工程成本高 |

### 3.3 气候区划（G2）——**推荐静态数据集而非 API**

建筑热工分区按行政区划是**慢变量**（区划表多年不变），做成随代码发布的静态映射表（`data/climate_zones.json`，标注出处与版本）比调 API 更可靠、零成本、可测试。**注意**：该表内容属规范衍生数据，入库时每条必须带 `source` 出处字段，且整表标 `pending_verification` 直至主理人核对签字（沿用 2.2.2 签字机制）。

### 3.4 太阳轨迹（G4）——**纯算法，无外部依赖**

太阳高度角/方位角为天文计算（如 NOAA 算法/`astral` 库），输入坐标+日期即可，无 API、无成本、结果可复算验证。建议列为 2.2.1 的“确定性事实”首选实现。

## 四、数据源 ADR 方案（待主理人决策）

### ADR-2.2.1-01：数据源接入架构 —— **推荐方案 C**

| 方案 | 描述 | 评估 |
|------|------|------|
| A. Agent 内直连 API | EnvironmentAgent 里直接 httpx 调第三方 | ❌ 耦合、无法 mock CI、换源要改 Agent |
| B. 独立 MCP 服务 | 起 weather_mcp/gis_mcp 独立进程 | ❌ 本阶段过重，部署面扩大 |
| **C. Provider 抽象层（推荐）** | 新增 `agents/environment/providers/` 包：`WeatherProvider`/`GeoProvider` 抽象基类 + 具体实现（真实源 / `mock` / `disabled`），配置驱动，复刻 2.1.6 LLM Provider 解耦模式 | ✅ 与既有架构同构；CI 走 mock 零外部依赖；换源仅换实现类 |

### ADR-2.2.1-02：数据源选型（**不在本文档拍板**，给出推荐组合供审）

- **推荐组合（待批）**：GeoProvider → 国内地图 API（A1/A2 二选一，待主理人确认账号主体与商用授权）；WeatherProvider → B1 Open-Meteo 起步（免费、历史统计够用），国内稳定性差则切 B2；气候区划 → 静态表（§3.3）；太阳轨迹 → 本地算法（§3.4）。
- **决策输入需主理人提供**：①商用/内部使用性质（决定授权层级）；②月预算上限；③是否已有企业地图账号。

### ADR-2.2.1-03：失败语义

任何 Provider 失败/超时/未配置 → **降级回现有 LLM 推理路径**，对应字段保持 `pending_verification=true` 并写入 gaps。真实数据接入**只增强、绝不阻断**现有链路（管道可用性不回退）。

## 五、API 设计（Provider 抽象契约，接口级，不含实现）

```python
# agents/environment/providers/base.py（设计稿）

@dataclass(frozen=True)
class GeoResult:
    lat: float | None
    lng: float | None
    province: str | None
    city: str | None
    district: str | None
    source: str                 # 数据源标识，如 "amap" / "mock"
    raw_ref: str                # 原始响应留痕 ID（脱敏后存 evidence）
    fetched_at: str             # ISO8601
    ok: bool
    error: str | None = None

@dataclass(frozen=True)
class WindClimate:
    prevailing_wind: str | None      # 如 "SE"（多年统计主导风向）
    avg_wind_speed_ms: float | None  # 多年平均风速
    stat_years: str | None           # 统计年限，如 "1991-2020"
    source: str
    raw_ref: str
    fetched_at: str
    ok: bool
    error: str | None = None

class GeoProvider(ABC):
    name: str
    @abstractmethod
    async def geocode(self, address: str) -> GeoResult: ...

class WeatherProvider(ABC):
    name: str
    @abstractmethod
    async def wind_climate(self, lat: float, lng: float) -> WindClimate: ...

# 工厂（配置驱动，复刻 2.1.6 模式）
def build_geo_provider(cfg) -> GeoProvider | None: ...      # disabled → None
def build_weather_provider(cfg) -> WeatherProvider | None: ...
```

**配置扩展**（`agents/config.yaml`，新增段，默认全 disabled——合入即零行为变化）：

```yaml
environment_data:
  geo:
    provider: disabled        # disabled | mock | <真实源名，ADR-02 批准后填>
    api_key: ${ENV_GEO_API_KEY:pending_verification}
    timeout_seconds: 8
  weather:
    provider: disabled
    api_key: ${ENV_WEATHER_API_KEY:pending_verification}
    timeout_seconds: 8
  solar:
    provider: local           # 纯算法，无 Key
  cache:
    backend: sqlite           # 见 §7
    ttl_days: 30
```

**Agent 集成点**：`EnvironmentAgent.invoke` 在 LLM 调用**之前**插入数据获取段——Provider 命中的字段进 `facts` 且计入 evidence；未命中字段继续走 LLM 推理并保持 pending。LLM 的 System Prompt 追加“以下为实测数据，禁止改写”段落（prompt.md 同步留底）。

## 六、evidence 结构设计

沿用 `agents/base.py::Evidence`（source/observed_at/confidence/content 四字段，不改基类）。真实数据命中时新增 evidence 条目：

```json
{
  "source": "environment.weather_provider",
  "observed_at": "2026-07-27T08:00:00Z",
  "confidence": "measured",
  "content": {
    "provider": "<ADR-02 批准后的源名>",
    "field": "prevailing_wind",
    "value": "SE",
    "stat_basis": "1991-2020 多年统计",
    "raw_ref": "cache:wind:23.35,116.68:v1",
    "fetch_status": "hit_cache"
  }
}
```

**confidence 三级约定**（写入 agent.md 契约）：

| 级别 | 含义 | pending_verification |
|------|------|---------------------|
| `measured` | 真实数据源返回，含出处与时间戳 | 该字段 **false** |
| `inferred` | LLM/规则常识推理 | 该字段 **true** |
| `unavailable` | 源失败且无法推理 | true + gaps |

**字段级 pending 细化**：输出新增 `field_provenance` 映射（如 `{"prevailing_wind": "measured", "climate_zone": "inferred"}`）；顶层 `pending_verification` 语义修正为“**存在任一非 measured 关键字段**即 true”。这修正 §1.2 指出的语义瑕疵，且不破坏既有消费方（顶层字段仍在）。

## 七、缓存设计

| 决策项 | 设计 | 理由 |
|--------|------|------|
| 后端 | **SQLite 单表**（`data/env_cache.db`，独立于业务库） | 零新依赖；风况/区划为慢变量，无需 Redis |
| Key | `{kind}:{lat:.2f},{lng:.2f}:{schema_ver}`（坐标截断 2 位小数 ≈ 1km 网格） | 相邻地址复用；防 Key 爆炸 |
| TTL | 风况统计 30 天；地理编码 90 天；太阳轨迹不缓存（纯计算） | 慢变量长 TTL，省额度 |
| 过期策略 | 惰性过期（读时判断）+ 命中过期数据且源失败时**降级返回旧值**并在 evidence 标 `stale=true` | 可用性优先，且留痕不隐瞒 |
| 并发 | 单进程内 asyncio lock 防击穿；不做分布式锁 | 当前部署形态单实例 |
| 隐私 | 缓存只存坐标网格与统计值，**不存用户原始地址** | 最小化留存 |

## 八、Mock 测试方案

1. **MockGeoProvider / MockWeatherProvider**：与 mock LLM 同构——返回结构合法的固定样本（样本值显式标注 `"__mock__": true`，且**不使用真实城市的真实风况数值**，避免 mock 数据被误当真实数据固化）。
2. **CI 恒走 mock/disabled**：`config.yaml` 默认 disabled；测试用例显式注入 mock Provider。**local_ci.sh 全程零外网请求**（延续 2.2 计划红线）。
3. **测试矩阵**（新增 `tests/agents/test_environment_providers.py` + 扩展 `test_environment.py`）：
   - 契约：mock Provider 返回结构完整、字段类型正确；
   - 命中路径：Provider 成功 → facts 填充 + evidence `measured` + `field_provenance` 正确 + 该字段 pending=false；
   - 降级路径：Provider 抛错/超时/disabled → 回落 LLM 推理，字段 pending=true + gaps 登记，**invoke 不抛异常**；
   - 缓存：写入→命中→过期→stale 降级 四态；
   - 防编造锁：mock 关闭且 LLM 关闭时，风况字段必须为 "不确定"（不允许出现任何具体数值）；
   - 回归：既有 8 个 environment 用例不改语义、全部保绿（基线 193 passed 只增不减）。
4. **真实源冒烟**（不进 CI）：单独脚本 `scripts/smoke/env_providers_smoke.py`，ADR-02 批准并配置 Key 后由主理人手动执行，结果人工核对后记入验收报告。
