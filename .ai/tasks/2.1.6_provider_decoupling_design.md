## 0. 现状基线（与已落地工作的关系）

Sprint 1 里已对 2.1.6 做过一次**局部落地**（作为"modality 解耦"子集）：

- `agents/llm/router.py`：`build_router_from_config(config, modality="text")`，`"vision"` 走 `llm.vision` 块（缺失回落 `track_a`），副轨恒为 `track_b`(mock)。
- `agents/vision/agent.py`：`_call_llm` 调 `build_router_from_config(llm_cfg, modality="vision")`。
- `agents/config.yaml`：已新增 `llm.vision` 独立块（同源 `${LLM_A_*}`）。
- `tests/agents/test_router.py`：5 项覆盖选块/回落/子块读取。

本次设计**不推翻上述工作，而是把它升级为目标四 provider 模型**：把软开关 `modality` 替换为显式 `ProviderRole`（text/vision/embedding/fallback），把 `track_a/track_b/vision` 旧键收敛为语义化的 `providers:` 注册表。已落地的 `vision` 块直接演进为 `providers.vision`，运行行为不变。

## 1. 当前调用链

```
业务 Agent（environment / design / vision）
   │  _call_llm()
   ├─ llm_cfg = load_llm_config()            # 读 config.yaml::llm，做 ${ENV} 插值
   ├─ router  = build_router_from_config(llm_cfg [, modality])
   │              ├─ text 类(environment/design): modality 缺省="text"
   │              │     → 主轨 config["track_a"]   (TokenHub 多模态)
   │              │     → 副轨 config["track_b"]   (mock 容灾)
   │              └─ vision: modality="vision"
   │                    → 主轨 config["vision"]     (TokenHub 多模态，同源)
   │                    → 副轨 config["track_b"]   (mock 容灾)
   └─ response, _ = await router.route(LLMRequest(...))

Core 聊天集成（OrchestratorChatService）
   │  _ensure_initialized()
   └─ build_router_from_config(self.config_path)   # ⚠️ 传的是"路径字符串"而非 llm dict
         → config.get("router") 在 str 上抛 AttributeError → 被 except 吞
         → self._router = None → _llm_enabled = False
         → 聊天永远走 pending_verification 占位（真实 LLM 增强从未生效）

NLU（IntentExtractor）
   │  不自己构造 router，接收外部传入的 router 实例（文本路由器）
   └─ 走 LLM 重写意图，失败降级规则结果
```

## 2. 存在问题

- **P1 — 角色未语义化命名**：当前是 `track_a`/`track_b` 双轨 + `modality` 软开关，没有 text/vision/embedding/fallback 的命名。新增 provider 类型（如 embedding/RAG）只能再叠 `modality` 分支，配置与代码都会膨胀。
- **P2 — 聊天集成 LLM 是死的（既有 bug）**：`orchestrator_chat_integration.py:55` 把 `config_path`（str）传给期望 `Mapping` 的 `build_router_from_config`，抛 `AttributeError` 被 `except` 吞 → `router=None` → 聊天真实 LLM 增强从未生效；且未传 `modality`。占位文案还写"填入 LLM_A_API_KEY / LLM_B_API_KEY"，但 `track_b` 已是 mock，只需 `LLM_A_*`。
- **P3 — text 与 vision 主轨语义不清**：vision 通过 `llm.vision` 块解耦，但默认回落 `track_a`；未来若 text 走便宜模型、vision 走专用多模态模型，当前配置粒度不够，且回落逻辑写死在 `build_router_from_config` 里。
- **P4 — fallback 未被显式建模**：副轨恒等于 `track_b`(mock)，无法配置"真实次级供应商"或分级 fallback（primary → secondary → mock）。
- **P5 — embedding 完全缺失**：全仓无任何 embedding 接口/配置/预留钩子（grep 仅在 `docs`/`docker-compose qdrant`/前端 `sessionStorage` 等噪声中出现），Phase 3 知识库/RAG 接入时缺乏落点。
- **P6 — 硬编码回落**：`vision 回落 track_a`、`track_b 恒为 mock` 是写死的，缺乏可配置的 provider 选择策略。
- **P7 — 配置文档漂移**：`orchestrator_chat_integration.py` 占位文案与 `docs/LLM.md` 部分段落仍提 `LLM_B_API_KEY`，与"track_b=mock"事实不符。

## 3. 目标架构

引入显式 **`ProviderRole`** 模型 + **`providers:` 注册表**，把 DualTrackRouter 的双轨语义固定为「主轨(provider for role) + 副轨(fallback_provider)」。

```
ProviderRole = { TEXT, VISION, EMBEDDING, FALLBACK }

业务 Agent（environment/design/vision）
   │  _call_llm(role=ProviderRole.TEXT | VISION)
   ▼
build_router_from_config(config, role)
   ├─ primary   = resolve_provider(config, role)        # TEXT→providers.text / VISION→providers.vision
   └─ secondary = resolve_provider(config, FALLBACK)     # → providers.fallback（mock）
   ▼
DualTrackRouter(primary, fallback, strategy, timeout)
   │  route(request)
   ▼
LLMResponse  ──(失败/关闭)──▶ pending_verification 占位（契约不变）

预留（无当前消费者）：
   build_embedding_provider(config) → EmbeddingProvider | None
      provider=disabled → None（Phase 3 知识库/RAG 再接具体向量模型）
```

**关键映射**（1:1，干净）：
- `text_provider`   = 文本推理主轨
- `vision_provider` = 视觉推理主轨（多模态）
- `embedding_provider` = 独立预留（不属于 DualTrackRouter）
- `fallback_provider` = 文本/视觉共用的容灾副轨

`DualTrackRouter` 本身**不变**（仍是 track_a=primary / track_b=fallback），只改"如何选 primary/secondary"。

## 4. 配置设计

`agents/config.yaml` 全量迁移到语义化 `providers:` 注册表（旧 `track_a`/`track_b`/`vision` 键移除；已确认除 `router.py` 外无代码读旧键，迁移安全）。

```yaml
llm:
  enabled: true

  # ── 命名式 provider 注册表（2.1.6 目标架构）──
  providers:
    text:                       # 文本推理主轨（与旧 track_a 同源）
      provider: openai_compat
      base_url: ${LLM_A_BASE_URL:pending_verification}
      api_key: ${LLM_A_API_KEY:pending_verification}
      model: ${LLM_A_MODEL:pending_verification}
    vision:                     # 视觉推理主轨（多模态；当前与 text 同源，可独立指向专用模型）
      provider: openai_compat
      base_url: ${LLM_A_BASE_URL:pending_verification}
      api_key: ${LLM_A_API_KEY:pending_verification}
      model: ${LLM_A_MODEL:pending_verification}
    embedding:                  # 向量/检索预留（暂不启用）
      provider: disabled        # disabled → build_embedding_provider 返回 None
      # base_url / api_key / model 接入时填
    fallback:                   # 容灾副轨（文本/视觉共用）
      provider: mock            # 不接真实网络；真实 key 在 .env（不入 git）
  # ── 路由策略（所有角色共用；未来可下放到 per-role）──
  router:
    strategy: fastest
    timeout: 30
```

**解析契约（伪代码）**：

```python
class ProviderRole(str, Enum):
    TEXT = "text"; VISION = "vision"
    EMBEDDING = "embedding"; FALLBACK = "fallback"

def resolve_provider(config, role: ProviderRole):
    block = (config.get("providers") or {}).get(role.value) or {}
    # 回落规则：VISION 缺 → TEXT；TEXT 缺 → mock；FALLBACK 缺 → mock
    if role is VISION and not block: block = providers.get("text", {})
    if not block or provider == "disabled": return MockProvider(...)  # 或 None（embedding）
    return _build_provider(block, default_name=role.value)

def build_router_from_config(config, role: ProviderRole = TEXT) -> DualTrackRouter:
    primary = resolve_provider(config, role)
    fallback = resolve_provider(config, FALLBACK)
    return DualTrackRouter(track_a_provider=primary, track_b_provider=fallback, ...)

def build_embedding_provider(config):
    block = (config.get("providers") or {}).get("embedding", {})
    if str(block.get("provider","disabled")).lower() == "disabled": return None
    # 未来：return EmbeddingProvider(...)
```

- `modality=` 旧参数**移除**，统一为 `role=`。3 个 Agent 调用点 + 测试 stub 同步改为 `role=`。
- `embedding_provider` 默认 `disabled` → `build_embedding_provider` 返回 `None`，**无消费者、无业务功能**，符合 Sprint 1 原则。

## 7. 风险

- **R1 — 漏改旧键读取**：全量迁移 `track_a/track_b/vision` → `providers:*`，若有隐藏读取点会 `KeyError`。缓解：grep 复查全仓 `track_a|track_b` 仅剩 router.py（已确认）；加 resolver 单测覆盖缺省结构。
- **R2 — embedding 过度设计**：本期仅留 `EmbeddingProvider` 抽象 + `disabled` 默认，不实现具体向量调用，避免返工与新增依赖。Phase 3 再接。
- **R3 — 聊天修复后首走真 LLM**：可能暴露下游未覆盖路径。缓解：保持"失败/关闭→pending_verification 占位"契约不变，加集成测试；`except` 仍兜底。
- **R4 — `modality→role` 重命名漏改**：3 Agent + 测试 stub + docs 需同步。缓解：全局 grep `modality=` 统一替换，CI 拦截 `TypeError`。
- **R5 — text/vision 同源配置重复**：当前两块内容相同（均 `${LLM_A_*}`）。本期接受少量重复；未来可加 YAML `&llm_defaults` anchor，不在本期范围。
- **R6 — 测试基线回退**：每步改完即跑 agent + backend + 前端测试，最后跑 `local_ci.sh` 门禁。
