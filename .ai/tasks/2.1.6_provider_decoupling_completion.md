## 1. 执行顺序与每步记录

### Step 1 — `router.py` ProviderRole + resolver 重构

- **改动文件**：`agents/llm/router.py`
  - 新增 `ProviderRole(str, Enum)`：`TEXT / VISION / EMBEDDING / FALLBACK`。
  - `build_router_from_config(config, role=ProviderRole.TEXT, modality=None)`：`modality` 经 `_modality_to_role` 映射为 `role`（deprecated 别名保留）；从 `llm.router` 子块读取 `strategy/timeout`。
  - 新增 `resolve_provider(config, role)`：命名注册表解析——`providers[role]`；`VISION` 缺块回落 `text`；旧 `track_a/track_b` 键兼容回落；`EMBEDDING` 命中 `disabled/` 返回 `None`；无块回落 `MockProvider`。
  - 新增 `build_embedding_provider(config)`：`provider=disabled → None`（不接具体服务）。
  - 更新 `__all__`。
- **文档更新**：`docs/LLM.md` §3 代码入口表补 `ProviderRole` / `resolve_provider`；`docs/AGENTS.md` §6 标注 `role=` 与 `modality=` deprecated。
- **测试**：`tests/agents/test_router.py` 重写（10 项，见 Step 5）。

### Step 2 — `config.yaml` providers 迁移

- **改动文件**：`agents/config.yaml`
  - 删除 `track_a/track_b/vision` 旧键，新增 `llm.providers:{text,vision,embedding,fallback}`：
    - `text` / `vision`：同源 `${LLM_A_*}`（腾讯混元 TokenHub，多模态）。
    - `embedding`：`provider: disabled`。
    - `fallback`：`provider: mock`。
  - 顶层注释说明：router.py 仍兼容旧 `track_a/track_b` 键，但本文件不再作为配置入口。
- **文档更新**：`docs/LLM.md` 引言段改 `providers.text/vision` 指向 TokenHub、`fallback=mock`、`embedding=disabled`；§2 切换指南改 `LLM_A_API_KEY` + `role=ProviderRole.TEXT`。
- **测试**：无新增，依赖 router resolver 兼容解析既有行为。

### Step 3 — Agent 调用 role 迁移

- **改动文件**：
  - `agents/vision/agent.py`：`build_router_from_config(llm_cfg, role=ProviderRole.VISION)`（原 `modality="vision"`）；移除未用 `import json`（ruff F401）。
  - `agents/environment/agent.py`：`build_router_from_config(llm_cfg, role=ProviderRole.TEXT)`。
  - `agents/design/agent.py`：`build_router_from_config(llm_cfg, role=ProviderRole.TEXT)`。
- **约束遵守**：三处均**未修改任何 Agent 业务 prompt**。
- **文档更新**：`docs/AGENTS.md` Agent 表 environment/design 标"走 `role=TEXT` provider"、vision 标"走 `role=VISION` provider"。

### Step 4 — 修复 `orchestrator_chat_integration.py` 路由初始化（P2 既有 bug）

- **改动文件**：`agents/core/orchestrator_chat_integration.py`
  - `_ensure_initialized()` 改为：先 `llm_cfg = load_llm_config(self.config_path)`，再 `self._router = build_router_from_config(llm_cfg, role=ProviderRole.TEXT)`。
  - **根因**：原代码把 `config_path`（str）直接传给期望 `Mapping` 的 `build_router_from_config`，`config.get(...)` 抛 `AttributeError` 被 `except` 吞 → `router=None` → 聊天真实 LLM 增强静默失效，且未传 `modality`。
  - 占位文案去掉 `LLM_B_API_KEY` 误导，仅保留 `LLM_A_API_KEY`。
- **文档更新**：`docs/LLM.md` §4 注脚标 Phase 2.1.6 已修复聊天路由初始化。
- **测试**：`tests/agents/test_orchestrator_chat_integration.py` 新增（见 Step 5）。

### Step 5 — 运行测试并输出报告

- **测试重写/新增**：
  - `tests/agents/test_router.py`：重写为 10 项（role 选块 / vision→text 回落 / fallback=mock / modality 弃用别名 / 旧键兼容 / embedding→None / router 子块 strategy/timeout）。
  - `tests/agents/test_orchestrator_chat_integration.py`：新增 `test_ensure_initialized_builds_router_when_enabled`（验证 P2 修复后 `llm_enabled is True` 且 `_router is not None`）+ `test_chat_returns_standard_envelope`（断言 `result.llm_enabled is True`）。

- **顺带修复 2.1.7 遗留扫描器倒退**（`scripts/lint/check_fabrication.py`）：`OUTLINE_SECTION_RE` 改行首前缀判定，避免把含数值的示例串误当大纲编号放行；新增表格 `|` 与字母紧邻编号（P0/R4/D1）跳过；真实业务数值仍被拦下。
