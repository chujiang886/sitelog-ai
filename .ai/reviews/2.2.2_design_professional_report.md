## 二、交付清单

### Step 1 — DesignAgent 语义修正（`agents/design/agent.py` → 1.1.0-phase2.2.2）
- **修复 P1（语义对齐 ADR-2.2.1 §7）**：LLM 成功**不再**自动 `pending_verification=False`；Level 0 inferred（LLM 推理）永远保持 `pending`。
- **顶层 pending 计算**：`pending_top = any(field_provenance[k] != "verified" for k in KEY_FIELDS)`，与 Environment 2.2.1 同构。
- **新增 `field_provenance`**：`inferred`（LLM）/ `verified`（已签字）/ `unavailable`（未产出）三态。
- **新增 `threshold_refs`**：候选字段 → 阈值 ID 引用槽位（仅引用，数值仍 pending）。
- **新增 `decision_trace`**：三方案原型（经济/舒适/高性能）差异化依据与可信等级。
- 失败/降级路径统一经 `_build_result_data` 装配，含溯源与 pending gaps。

### Step 2 — 阈值治理机制
- **`agents/design/thresholds/verified.json`**（新建）：`schema_version=1` + `D-TH-01~05` 五项，全部 `verified=false`、`value=null`、`verified_by/verified_at=null`（单一签字库，审计清晰）。
- **`agents/design/threshold_loader.py`**（新建）：
  - `load_verified_thresholds(path=None)` — 缺省指向默认路径；文件缺失/解析失败 → 返回 `{}`（等价全 pending，合入即零行为变化）。
  - `is_fully_verified(entry)` — `verified=true` 且 `verified_by`+`verified_at` 俱全才认签字（一票否决）。
  - `resolve_field_provenance(verified, produced)` — 计算字段级溯源。
  - `build_threshold_refs()` — 字段 → 阈值 ID 引用。
  - `KEY_FIELDS` / `THRESHOLD_FIELD_MAP` / `FIELD_THRESHOLD_REF` 映射常量。
- **`agents/config_loader.py`**：新增 `load_verified_thresholds`（与 `load_environment_data_config` 对称 SSOT 入口，委托 threshold_loader）。

### Step 3 — Prompt 专业化
- `SYSTEM_PROMPT`：环境感知约束（实测 marked measured / 推理 marked inferred）、经济/舒适/高性能三方案原型框定（成本—舒适—性能三角取舍）、阈值引用槽位说明、强化不杜撰（禁止输出具体风压/壁厚/玻璃厚度等数值）。
- `USER_PROMPT_TEMPLATE`：环境事实渲染为带可信度标签文本（`climate_zone=XX(measured/inferred)`），契约字段不变。
- 全部文案 numeric-free，不触编造扫描（CI 第 7 步通过）。
