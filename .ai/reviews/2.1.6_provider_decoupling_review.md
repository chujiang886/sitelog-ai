## 2. Provider 架构变化前后对比

| 维度 | 改造前（Phase 2 早期） | 改造后（2.1.6） |
|---|---|---|
| 角色模型 | 无语义枚举；仅 `modality="vision"` 软开关 | `ProviderRole`（TEXT/VISION/EMBEDDING/FALLBACK）语义枚举 |
| 配置结构 | `llm.track_a` / `llm.track_b` / `llm.vision` 分散键 | 统一 `llm.providers:{text,vision,embedding,fallback}` 命名注册表 |
| 解析入口 | `build_router_from_config(config, modality=)` | `build_router_from_config(config, role=, modality=deprecated)` + `resolve_provider(config, role)` |
| 文本/视觉分流 | 视觉 Agent 借 `modality="vision"` 读 `llm.vision`（缺省回落 track_a） | 三 Agent 显式 `role=TEXT/VISION`；vision 缺块回落 text |
| 容灾副轨 | 恒 `track_b`（mock） | 恒 `ProviderRole.FALLBACK`（mock） |
| embedding | 无角色概念 | `EMBEDDING` 角色预留，`provider=disabled → None` |
| Orchestrator 聊天 | `config_path`(str) 误当 Mapping → `router=None`（真实 LLM 增强失效） | 先 `load_llm_config` 再 `build_router_from_config(role=TEXT)` |
| 旧键兼容 | — | `track_a/track_b` 仍被 `resolve_provider` 兼容解析（不作新入口） |

## 3. ProviderRole 实现情况

**枚举定义（`agents/llm/router.py:31-44`）**
```python
class ProviderRole(str, Enum):
    TEXT = "text"
    VISION = "vision"
    EMBEDDING = "embedding"
    FALLBACK = "fallback"
```
- ✅ 4 个语义成员到位，均为 `str` 枚举，可直接与配置字符串比较。
- ✅ `build_router_from_config` 支持 `role=ProviderRole.*`，`modality=` 经 `_modality_to_role` 映射为角色（deprecated）。
- ✅ `resolve_provider(config, role)` 实现命名注册表解析：角色块读取 → vision→text 回落 → 旧键兼容回落 → embedding→None → 无块回落 MockProvider。
- ✅ `build_embedding_provider(config)`：`provider=disabled → None`，不引入具体向量服务。

⚠️ **偏差（验收发现）**：当前枚举**缺少 `UNKNOWN` 防御状态**。上一条编码指令（`ProviderRole 增加 UNKNOWN 防御状态`）因服务错误在落盘前中断，**未进入代码**。因此当前 `build_router_from_config` 在收到非法角色字符串时仍会抛 `ValueError`（`ProviderRole(str(role))` 未做 try/except 防御），不满足"防御状态"要求。详见 §9。

## 4. text / vision / fallback / embedding 四角色状态

| 角色 | 配置块 | resolver 行为 | 状态 |
|---|---|---|---|
| `TEXT` | `providers.text`（TokenHub `${LLM_A_*}`） | 主轨；缺块则回落旧 `track_a` | ✅ 正常 |
| `VISION` | `providers.vision`（同源 TokenHub） | 主轨；缺块回落 `providers.text` | ✅ 正常（当前与 text 同源，架构已支持分离） |
| `FALLBACK` | `providers.fallback`（mock） | 恒为容灾副轨 | ✅ 正常 |
| `EMBEDDING` | `providers.embedding`（`provider: disabled`） | `disabled → None`；预留接口，不接服务 | ✅ 符合"仅预留、本阶段不新增实际模块"约束 |

> `C4`（单 track_a 多模态混用）已通过 `providers.text` / `providers.vision` 分离配置偿还；当前二者指向同一 TokenHub 属运行选择，架构层面分离已具备。

## 6. Orchestrator 修复情况

- **根因（P2 既有 bug）**：`orchestrator_chat_integration.py` 原 `_ensure_initialized` 把 `self.config_path`（字符串）直接传给期望 `Mapping` 的 `build_router_from_config`，`config.get(...)` 抛 `AttributeError` 被 `except` 吞 → `router=None` → **聊天真实 LLM 增强静默失效**，且未传 `modality`/`role`。
- **修复（已验证）**（`orchestrator_chat_integration.py:53-61`）：
  ```python
  llm_cfg = load_llm_config(self.config_path)
  self._router = build_router_from_config(llm_cfg, role=ProviderRole.TEXT)
  ```
  占位文案已去 `LLM_B_API_KEY` 误导。
- ✅ 测试：`tests/agents/test_orchestrator_chat_integration.py::test_ensure_initialized_builds_router_when_enabled` 断言 `llm_enabled is True` 且 `_router is not None`，通过。
- ⚠️ **残余（不属本任务范围，已单列）**：`chat()` 内 `response = await self._router.route(request)` 把 `route()` 返回的 `(response, results)` 元组赋给 `response`，后续 `.finish_reason` 抛 `AttributeError` 被捕获 → `chat()` 返回 `success=False`。影响聊天实际出文成功率，不影响 `llm_enabled` 标志与路由构建。建议后续单独修 `route()` 返回值解包。
