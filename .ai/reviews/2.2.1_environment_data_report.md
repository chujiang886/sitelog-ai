## 二、架构决策（ADR-2.2.1 要点）

1. **方案 C：Provider 抽象层**（复刻 2.1.6 LLM Provider 解耦）——抽象基类 + 配置驱动工厂 + `mock`/`disabled` + 注册表扩展位。换源仅换实现类，Agent 零改动。
2. **三模式**：`disabled`（默认，零行为变化）/ `mock`（CI 零外网）/ `<真实源名>`（ADR-02 批准后经 `register_*_provider` 接入）。
3. **强制溯源三字段**：`source` / `fetched_at` / `raw_ref`（所有 Provider 结果缺一即构造失败，fail-fast）。
4. **`real_data` 真实性锁**：仅真实外部源返回 `True`；mock 恒 `False`，下游据此禁止标 `measured`（R-01 红线第一重锁）。
5. **字段级溯源 `field_provenance`**：`measured` / `mock` / `inferred` / `unavailable`。
6. **顶层 `pending_verification` 语义修正**：存在任一非 `measured` 关键字段（climate_zone / prevailing_wind / solar_exposure）即为 `True`——LLM 推理属 Level 0（inferred），永远 pending（修复 Phase 1 瑕疵，非降标）。
7. **Environment 数据可信等级模型**：Level 0=LLM inferred / Level 1=Measured source / Level 2=Expert verified / Level 3=Engineering approved。
8. **降级语义（ADR-03）**：Provider 失败/超时/未配置 → 降级回 LLM 推理路径，只增强绝不阻断（`invoke` 永不因数据源崩溃）。
