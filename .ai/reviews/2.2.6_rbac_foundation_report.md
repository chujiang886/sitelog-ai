## 4. 认证架构

- JWT HS256：payload `{sub, tenant_id, email, role, roles[], permissions[], iat, exp, type:"access"}`，TTL 60 分钟。
- secret 仅来自 `.env::JWT_SECRET`，`_get_jwt_secret` fail-closed（缺失即抛 AuthConfigError，拒绝签发/校验）。
- 权限在登录时嵌入 token（免每请求查库）；`get_current_user` 解析 Bearer → 校验签名/过期/类型 → 校验用户 active 且未删除。
- 刷新策略：本阶段仅 access token（60min 过期重登录）；refresh token 列入后续（见 §9）。

## 5. 权限架构

- 命名规则 `resource:action`：`upload:create/read`、`analysis:create/read`、`report:create/read`、`user:manage`、`tenant:manage`。
- 角色映射：admin=全部；designer=upload/analysis/report 全读写；viewer=仅 read（不可 upload/analysis:create/report:create）。
- `require_permission(perm)` 工厂：无 token → 401；有 token 无权限 → 403 `Permission denied: requires 'xxx'`（明确返回）。

## 9. 遗留风险

| 风险 | 级别 | 说明 |
|---|---|---|
| 无 refresh token | 中 | 60min 过期需重登录；企业化正式版需 refresh + 吊销机制 |
| 前端未接登录流 | 中 | /login 页面尚未对接 /api/auth/login；受保护 API 前端调用需带 Bearer（当前前端不调用这三个受保护写端点的页面不受影响） |
| 权限固化于 token | 低 | 改角色需重登录生效；后续可加 token 版本号强制失效 |
| User.role 遗留列与 user_roles 双轨 | 低 | 授权只认 user_roles；遗留列待后续迁移收敛 |
| 存量用户密码为占位符 | 低 | 旧 seed 用户 hashed_password="pending_verification" 无法登录（预期行为，需重 seed 或管理员重置） |
| TD-008 密钥管理基建 | 中 | JWT_SECRET 目前手工放 .env；正式环境需 Vault/云密钥 |
