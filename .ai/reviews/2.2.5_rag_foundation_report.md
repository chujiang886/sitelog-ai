## 1. 任务概述与目标

建立 BOIP 知识库 RAG 基础能力（"基础设施"，非端到端问答）：

- **knowledge ingestion**：文档分块 → 向量化 → 入库，强制溯源。

- **vector storage 接口**：InMemory（默认）+ Qdrant（可选，懒加载）。
- **search API**：向量检索，返回带溯源的命中片段。

**红线**（来自指令）：禁止直接接入真实 Embedding 服务（默认 mock）；禁止无来源知识入库。

## 3. 架构要点

### 3.1 复用 ProviderRole.EMBEDDING（不重建 LLM 体系）
- `agents/llm/embedding.py` 与现有 LLM provider 同包，复用 `ProviderRole.EMBEDDING` 语义角色与 `openai_compat.py` 的 `urllib` 同步 POST 模式。
- `EmbeddingProvider` 是**单 provider**（非双轨），与 `DualTrackRouter` 解耦——RAG 检索不需要双轨容灾。
- `router.build_embedding_provider(config)` 扩展为真正构造 provider：`disabled→None`（兼容旧行为）、`mock→MockEmbeddingProvider`、`openai_compat`（凭据解析后）→真实 provider，凭据缺失回落 mock。

### 3.2 Embedding 接口（默认不直连真实服务）
- 运行时工厂 `get_embedding_provider()` 读 `BOIP_EMBEDDING_PROVIDER`（**默认 `mock`**）。
- `mock`：确定性哈希向量（相同文本→相同向量，内容相似→余弦更高），零外部依赖。
- `openai_compat`：读 `EMBEDDING_*` env（缺省回落 `LLM_A_*` 同源，因 TokenHub 兼服 embeddings），**仅显式配置后启用**；凭据缺失自动回落 mock。
- 默认配置下**绝不建立真实 Embedding 网络连接**，满足"禁止直接接入真实 Embedding 服务"。

### 3.3 Vector Storage 接口（CI 不依赖外部 Qdrant）
- `InMemoryVectorStore`：默认（dev/CI），进程内单例，余弦检索。
- `QdrantVectorStore`：生产可配置，懒加载 `qdrant_client`（**不进硬依赖**），未配置→fail-fast `VectorStoreConfigError`；payload 带溯源三要素。
- `get_vector_store()` 读 `BOIP_VECTOR_STORE`（**默认 `memory`**）→ CI 永不 import 真实 SDK。
- **单例缓存**：ingest 与 search 共享同一 store（跨请求状态一致），并提供 `reset_*` 供测试隔离。

### 3.4 文档 chunk 策略
- `chunk_text`：按 `\n` 切段落→贪心累积→单段超长时字符窗口硬切带 `overlap`；空文本返回 `[]`；`overlap ∈ [0, chunk_size)` 校验。

### 3.5 溯源设计（防编造 / 强制来源）
- `ingest_document` 校验 `source` / `raw_ref` 非空 + `text` 非空，任一缺失→`IngestionError`（拒绝入库），落实"禁止无来源知识入库"。
- 每条入库对象 metadata 强制携带 `source` / `created_at`（自动打 UTC）/ `raw_ref` / `tenant_id` / `chunk_index`；检索结果原样返回这三要素，使上层可追溯、可审计。

### 3.6 检索 API
- `POST /api/rag/ingest`：带溯源知识入库；校验失败返回 `INGESTION_REJECTED` 信封（不 422 吞掉）。
- `POST /api/rag/search`：embed(query) → vector store search → 返回 `{items:[{id,score,text,source,created_at,raw_ref,chunk_index}]}`。
- `GET /api/rag/mode`：可观测当前 embedding/vector store 后端类型（确认未误连真实服务）。

## 6. 架构影响

- **RAG 地基成型**：embedding 接口 + 向量存储抽象 + 入库 + 检索 API 四件套齐全，上层（未来问答链）可直接消费，无需触碰底层 provider。
- **生产就绪开关**：真实 Embedding（openai_compat）与 Qdrant 经环境变量切换，默认 mock/memory，零误连风险。
- **溯源闭环**：所有入库知识强制 `source/created_at/raw_ref`，检索可回链原文——为后续"答案标注 pending / 不伪装成已确认事实"奠定基础。
- **零回归**：仅新增 router + 端点，既有 API 契约不变；前端无需改动。
