## 三、能力交付（对照需求清单）

| 需求 | 落地 |
|---|---|
| 1. 项目基础信息 | 封面扩充：地址 / request_id / 预算档位 / 风格偏好 / 约束条件 |
| 2. 环境分析 | 二、环境分析：字段表 + 可信度列；消费 `field_provenance` |
| 3. 数据可信等级说明 | 三、新增章节：Level 0~3 模型 + 如何读徽标 |
| 4. 设计方案对比（经济/舒适/高性能） | 四、按 `estimated_cost_tier` 映射三原型，逐方案展开 |
| 5. 每方案：依据/优势/限制/待验证项 | 四、每方案渲染 依据说明/优势/限制/`待验证项`（未签字阈值 + gaps） |
| 6. 明确展示 已验证/推理/待确认 | 统一徽标 `[已验证]`/`[AI推理·待确认]`/`[待确认]`；Environment evidence 子表列 `real_data` |

**Environment evidence 展示**：逐 `data_providers` 列出来源名 / 类型 / 是否实测 / 获取时间；
未配置真实源（默认 disabled / mock）显式标注 `real_data=false`，绝不渲染为实测。

**Design provenance 展示**：每方案 provenance 脚注列出 `field_provenance` 与 `threshold_refs`
ID；`verified.json` 全 `false` 时全文档不出现 `[已验证]` 绿标。

**防编造红线**：凡非 verified 字段一律标 `[AI推理·待确认]` 或 `[待确认]`；`gaps` 中
`design_threshold:*` 条目透出在「待验证项」；无任何业务数值被渲染成确定性工程结论。
