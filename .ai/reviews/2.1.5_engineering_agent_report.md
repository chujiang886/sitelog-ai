## 三、接口契约

### 3.1 五个分析接口（稳定标识）

| 接口标识 | 职责 | 骨架行为 |
|---------|------|---------|
| `wind_pressure` | 风压分析接口 | 返回统一结构，不产出数值 |
| `glass_safety` | 玻璃安全接口 | 返回统一结构，不产出配置结论 |
| `profile` | 型材分析接口 | 返回统一结构，不产出选型结论 |
| `hardware` | 五金分析接口 | 返回统一结构，不产出选型结论 |
| `installation_risk` | 安装风险接口 | 返回统一结构，不产出风险等级 |

### 3.2 统一输出结构（任务规定）

```json
{
  "result": "",
  "confidence": "",
  "evidence": "",
  "verification_status": "pending_verification"
}
```

- 事实源：`build_skeleton_output()`；字段集 = `REQUIRED_OUTPUT_KEYS`（validation.py）。
- 测试锁死：字段恰好四个、顺序一致、内容字段为空串、状态恒为 `pending_verification`。

### 3.3 invoke 契约

- `input_data.analyses` 缺省 → 执行全部五接口；给子集 → 只执行子集。
- 未知接口名 → `success=false` + `error.code=ENGINEERING_UNKNOWN_INTERFACE`。
- `data` 携带：`analyses`（逐接口统一结构）、`review_chain`（逐接口审核记录）、`pending_verification=true`、`gaps`（逐接口显式缺口）。

## 四、审核链与验证机制（EngineeringValidation）

- **抽象契约**：`EngineeringValidation.validate(interface, payload) -> 审核记录`，记录含 `interface / structure_valid / missing_keys / verification_status / validator`。
- **骨架实现**：`PendingEngineeringValidation` 只做结构校验（四字段齐备性）；结构合法也**必须**保持 `pending_verification`——骨架无真实验证能力；结构缺失 → `invalid_structure`。
- **可演进**：验证器通过构造注入（`EngineeringAgent(validator=...)`），Phase 3+ 换接真实规范库实现时 Agent 侧零改动。测试已验证自定义验证器注入与调用顺序。
