## 架构影响

- **请求路径全异步 DB 访问**：async 路由不再因同步 `db.commit()` / `db.query()` 阻塞事件循环，THD-012（Session 同步/异步）风险消除。
- **向后兼容**：同步 `get_db` / `SessionLocal` / `engine` 原样保留。
  - `vision_tasks.process_image` 继续用同步 `SessionLocal`（业务逻辑零改）。
  - `test_db.py` 直接断言同步 `get_db/SessionLocal/engine` —— 因保留而自动适配。
  - alembic `env.py` 维持同步引擎（应用运行时走异步，迁移走同步，URL 并存）。
- **解耦策略**：`process_image` 经 `asyncio.to_thread` 在后台线程执行，路由事件循环不被阻塞；其写入结果通过「同一临时文件库」对测试可见（生产环境真实 DB 天然共享）。
- **新增运行时依赖**：`aiosqlite`（SQLite 异步驱动），`session.py` 导入即 `create_async_engine("sqlite+aiosqlite:///:memory:")`。

- **backend 测试：64 passed / 0 failed**（覆盖 conversations / uploads / vision / db 同步路径）
- **agents 测试：86 passed / 0 failed**
- **合计：150 passed，0 失败，无告警**

**验证过程中暴露并修复的 3 个问题（均为 2.1.4 实施范围内的收尾，未触碰禁止项）：**

1. **`greenlet` 缺失（阻断 import）**：SQLAlchemy 2.0 异步引擎运行须依赖 `greenlet`，但 `backend/.venv` 预装缺失。补充 `greenlet>=3.0` 至 `backend/requirements.txt` 并安装（3.5.4）。这是「新增 aiosqlite」决策的连带运行时依赖，非范围扩张。
2. **测试 override 的 `AsyncSession` 默认 `expire_on_commit=True`**：生产 `AsyncSessionLocal` 为 `expire_on_commit=False`。override 用默认值时，`db.commit()` 后实例被 expire，访问 `.id` 触发异步会话上的惰性同步刷新 → `MissingGreenlet`。已将 3 个测试 override 的 `AsyncSession` 显式对齐生产配置（`expire_on_commit=False, autoflush=False, autocommit=False`）。
3. **`vision.py` 重载读不到 `process_image` 提交**：原重载 `select(Image).filter_by(...).one()` 返回 identity-map 中缓存的 `Pending` 旧实例，且 async 会话持有 `SELECT` 时的旧事务快照，看不到其他线程已提交的 `Done/Failed`。改为 `await db.rollback()` + `await db.refresh(image)`（结束旧快照、从 DB 重新读取最新行）。属 Step 3 路由改造的收尾修正，非业务逻辑改动。
4. **（附）fixture 中 `async_engine.dispose()` 协程未 await 告警**：已改为 `asyncio.run(async_engine.dispose())`，消除全部 26 条 RuntimeWarning。

**静态核查结论（同前，仍成立）：** 全 `backend` 仅 `session.py`/`db/__init__.py`/`test_db.py` 引用 `get_db`；3 路由 + 3 测试已全部切 `async_get_db`；无 `.query(` 同步遗留。
